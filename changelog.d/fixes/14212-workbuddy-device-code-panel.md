- **fix(providers):** adding a WorkBuddy connection no longer fails with "Browser OAuth is unavailable for this provider in the current environment". WorkBuddy is a device-code provider, but it was missing from the `DEVICE_CODE_PROVIDERS` set in the OAuth modal, so `startOAuthFlow` fell through to the browser-authorize branch. That branch is answered with `authUrl: null` for any `device_code` provider — correct behaviour that the modal then rendered as an environment failure. The modal now opens the device-code panel, and a regression test reconciles both lists so a future device-code provider cannot be registered on the backend only. ([#14212](https://github.com/diegosouzapw/OmniRoute/pull/14212))
